# 정보 과제 제출함 1.0.1

GitHub Pages 배포는 [접속 안내 페이지와 실제 서버의 구분](docs/GitHub-Pages배포.md)을 먼저 확인하세요. Pages만으로는 파일 제출·교사 로그인·DB 저장을 실행할 수 없습니다. 보안 재검토 및 수정 결과는 [공개 전 보안 검토](docs/공개전보안검토.md)에 정리했습니다.

학생이 파일을 제출하고 교사가 학급별로 확인·다운로드하는 웹사이트입니다. 학생과 교사 PC에는 크롬/엣지 외에 별도 개발 도구가 필요하지 않습니다. **서버 PC 한 대에는 Node.js 24 LTS와 아래 설치 작업이 필요합니다.** Electron 프로그램이나 Windows 설치 EXE는 아닙니다.

현재 결과물은 **로컬 개발·검증용**입니다. 실제 학생 자료를 넣기 전에 학교에서 승인한 서버·HTTPS·접근 범위·개인정보 처리 기준을 설정해야 합니다. 외부 서비스 연결, 클라우드 업로드, 유료 서비스, 분석 수집 코드는 없습니다.

## 서버 담당자의 처음 설치

1. 학교에서 승인한 Windows 11 x64 서버 PC에 공식 Node.js 24 LTS와 pnpm을 준비합니다. 학생 PC에는 설치하지 않습니다. `node --version`으로 24.15 이상, 25 미만을 확인합니다.
2. 이 폴더에서 다음 명령을 실행합니다. 패키지를 받는 최초 설치에는 인터넷이 필요합니다. `pnpm-lock.yaml`을 보존합니다.

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
Copy-Item .env.example .env
pnpm admin
pnpm start
```

3. `pnpm admin`은 아이디와 화면에 표시되지 않는 12자 이상 비밀번호를 묻습니다. 기본 관리자나 운영용 공용 비밀번호는 없습니다. 기존 아이디로 실행하면 비밀번호가 바뀌고 해당 세션이 종료됩니다.
4. 같은 PC에서 학생 화면 [http://127.0.0.1:4310](http://127.0.0.1:4310), 교사 화면 [http://127.0.0.1:4310/teacher](http://127.0.0.1:4310/teacher)에 접속합니다. 이 주소는 다른 PC에서 접속하는 학교 주소가 아닙니다.
5. 이후에는 `서버시작.cmd`로 시작할 수 있습니다. 서버 창을 닫으면 접속도 종료됩니다. Windows 서비스 설치나 관리자 권한은 자동 요청하지 않습니다.

완성된 `dist`도 ZIP에 포함되어 있습니다. 소스를 바꾸지 않으면 다시 빌드하지 않아도 됩니다. 서버 의존성만 설치하려면 `pnpm install --prod --frozen-lockfile --ignore-scripts`를 사용합니다.

## 사용 순서

교사: 로그인 → 학생 관리에서 명단 CSV 등록 → 과제 만들기 → 제출 코드와 접속 주소 안내 → 제출 현황 확인 → 전체 다운로드. CSV 서식은 `docs/가상명단예시.csv`를 참고하세요. 학년/반 추가와 최대 번호 변경도 학생 관리에서 합니다.

학생: 접속 → 학년·반·번호·이름 → 과제와 제출 코드 → 파일 선택/끌어놓기 → 확인 → 제출. 서버 저장이 완료되면 확인번호가 나옵니다. 확인번호는 다른 사람에게 알려주지 말고 보관합니다. 재제출은 동일한 학년·반·번호와 이전 확인번호가 필요합니다. 다른 학생의 파일 조회 기능은 없습니다.

파일은 과제당 한 개씩 제출합니다. 여러 파일은 안전 정책에 맞는 ZIP으로 묶습니다. 이전 제출본은 삭제하지 않으며 교사는 이력에서 다운로드할 수 있습니다. 확인번호를 잃으면 복구할 수 없습니다. 교사가 기존 파일을 보존하고 별도 과제를 만들어 다시 제출받습니다.

명단 미등록 상태에서는 미제출자와 제출률을 표시하지 않습니다. 명단 일부만 등록한 경우 통계도 등록된 학생만 기준으로 합니다. 이름이 명단과 다르면 교사 표에 함께 표시되므로 확인하세요. 제출 코드는 학생 본인 인증을 보장하지 않습니다.

## 저장·백업·복원·업데이트·제거

Windows 기본 저장 위치는 `%LOCALAPPDATA%\InformationAssignmentBox`입니다. `DATA_DIR`로 다른 비공개 폴더를 지정할 수 있습니다. `data.sqlite`는 명단·과제·이력·계정, `files`는 원본 제출 파일, `tmp`는 처리 중 파일, `backups`는 관리자 생성 백업입니다. 소스와 공개 웹 폴더에 자료를 두지 마세요. 외부 클라우드 동기화 폴더를 기본 저장소로 쓰지 마세요.

설정 → 전체 백업 만들기 → ZIP 다운로드로 백업합니다. 또는 `pnpm backup D:/학교승인저장소/새백업.zip`. CLI 백업은 제출·정리 작업이 없는 시간에 실행하세요. SQLite 일관된 스냅샷과 모든 제출 이력을 포함하고 로그인 세션은 제외합니다. 누락/무결성 오류가 있으면 실패합니다.

복원: 서버 종료 → `pnpm restore D:/백업.zip D:/새복원폴더` → `.env`의 `DATA_DIR`을 새 폴더로 변경 → 서버 재시작 → 명단·과제·파일 확인. 기존 폴더를 덮어쓰지 않으며 새 폴더만 허용합니다. 백업에는 개인정보와 계정 해시가 있으므로 접근을 제한하세요. **백업 ZIP은 암호화되지 않습니다.** 학교 승인 암호화 저장장치를 이용하세요.

업데이트: 전체 백업 → 서버 종료 → 새 버전 소스/의존성/빌드 교체 → 기존 `.env` 및 `DATA_DIR` 유지 → 서버 재시작·파일 점검. 데이터베이스 구조를 변경하기 전 자동 백업을 남기도록 초기화 코드에 마련했습니다. 실제 향후 버전 간 업그레이드는 아직 검증할 수 없습니다.

설정에서 보유기간 지난 제출 자료를 수동 정리할 수 있습니다. 정확한 확인 문구를 입력해야 합니다. 학생 명단·기존 ZIP·브라우저에서 받은 파일은 별도로 관리·삭제합니다. 프로그램 폴더를 제거해도 사용자 데이터는 자동으로 지우지 않습니다. 삭제할 자료는 학교 보유기간 기준을 따르세요.

## 개발·검증 명령

```powershell
pnpm test
pnpm test:ui
pnpm build
pnpm licenses
node scripts/package.mjs
```

개발 화면은 `.env`의 `APP_ORIGIN=http://127.0.0.1:5173`로 바꾼 뒤 터미널 두 개에서 `pnpm server`, `pnpm dev`를 실행합니다. 빌드 화면을 사용하려면 다시 4310 주소로 되돌리세요. `.env`는 배포 ZIP과 Git에서 제외됩니다.
