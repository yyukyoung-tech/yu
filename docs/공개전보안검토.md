# GitHub 공개 전 보안·개인정보 재검토

2026-11-07, 1.0.1 기준. 실제 학생 자료 없이 소스·설정·패키지·공개 산출물을 확인했습니다. 침투 테스트나 학교의 운영 승인을 대신하지 않습니다.

## 발견과 수정

1. 서버 의존성의 알려진 취약점 3건: csv-parse 6.x, archiver 7.x 경유 glob/minimatch. csv-parse 7.0.3, archiver 8.0.0으로 갱신하고 간접 minimatch를 11.0.1에 고정했습니다. 압축 API 변경은 작은 어댑터로 반영했습니다.
2. 전체 의존성 검사에서는 Vitest/Mocker/Tinypool 관련 개발 도구 권고 5건도 확인했습니다. Vitest 5.1.0으로 갱신하여 함께 해소했습니다. 전체 audit 재검사 결과 알려진 취약점 0건입니다. 이는 검사 시점의 권고 데이터 기준입니다.
3. 잘못된 DATA_DIR로 소스/웹 공개 폴더에 DB를 만들 수 있었던 설정 위험을 수정했습니다. 실제 경로를 확인해 심볼릭 링크 경유를 포함하여 앱 폴더 내부 저장을 시작 시 거부합니다. 회귀 테스트를 추가했습니다.
4. Git 제외 규칙을 `.env*`, DB, 키/인증서, 원본 파일, 업로드, 백업, 자료 폴더와 스크린샷까지 확대했습니다. 배포 ZIP 생성도 환경변수·키·DB·자료 폴더를 제외하도록 보강했습니다.
5. Pages에는 이름·번호·파일 입력창이나 제출 API를 포함하지 않고 안전한 안내 페이지로 분리했습니다. 학교 서버 주소가 없으면 제출 기능을 제공하지 않습니다. 잘못된 HTTP/토큰 포함 URL은 빌드 단계에서 거부합니다.
6. Actions는 확인한 공식 커밋 SHA에 고정합니다. 소스 읽기와 배포 권한을 작업별로 나누고, 개인정보/백업/서버 대신 안전한 `pages-dist`만 업로드합니다.

## 확인한 사항

소스에서 실제 학생 DB/제출 자료나 일반적인 비공개 키·GitHub 토큰·Firebase 관리자 키 패턴은 발견하지 않았습니다. 운영 계정의 비밀번호·개인정보가 없는 가상 테스트만 포함됩니다. 숨겨진 모든 종류의 개인정보를 자동 판별했다는 의미는 아닙니다.

기존 서버의 관리자 인증·HttpOnly/Secure/SameSite 세션·CSRF·제출 확인번호·비공개 저장·파일 검증·SQL 매개변수·실패 시 롤백을 다시 읽고 테스트했습니다. Pages에서 교차 사이트 쿠키 허용이나 인증 우회 코드를 추가하지 않았습니다. 로그인 세션과 학생 자료를 GitHub에 저장하지 않습니다.

GitHub 호스팅은 방문자의 접속 IP 등 서비스 제공을 위한 정보를 처리할 수 있습니다. 이 페이지는 자체 추적 도구를 넣지 않았지만, 외부 호스팅 자체가 학교 정책에 맞는지는 학교에서 확인해야 합니다. 실제 학생 정보의 외부 저장은 학교 승인 전에 활성화하지 않습니다.

## 남은 운영 조건

실제 제출은 학교 승인 서버, 유효한 HTTPS, 저장소 접근 제한·보유기간·백업 정책이 필요합니다. 제출 코드는 본인 인증이 아니며, 백신 검사와 300명 동시 대용량 부하는 별도 검증이 필요합니다. 공격자가 허용된 코드를 알아내 제출을 시도할 위험에 대비해 교실 네트워크 접근 제한을 권장합니다. 이번 변경에서 서버를 인터넷에 공개하지 않았습니다.

GitHub 등록과 Pages 실제 배포 성공 여부는 워크플로 및 반환 URL을 확인한 뒤 별도로 보고합니다. 로컬 파일과 설정만으로 배포 완료라고 간주하지 않습니다.
