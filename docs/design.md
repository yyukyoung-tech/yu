# 정보 과제 제출함 설계

사용자 첨부 요구사항이 설계 기준이다. 학생은 브라우저에서 회원가입 없이 제출하고 교사는 로그인해 수합한다. Electron 요구는 최신 웹사이트 요청으로 대체한다. 외부 게시·클라우드·실제 개인정보 전송은 하지 않는다.

## 구조와 선택
React + TypeScript + Tailwind, Node.js 24 + Express, 로컬 SQLite WAL, 비공개 파일 디렉터리. 단일 프로세스 학교 내부 서버를 기본으로 하고 HTTPS는 학교 역방향 프록시 또는 제공된 TLS 인증서로 종료한다. PostgreSQL은 다중 서버 확장이 필요할 때 이전하며, 이번 버전은 32개 동시 제출로 단일 서버 적합성을 검증한다. 외부 호스팅은 승인 전 활성화하지 않는다.

## 화면
학생: 학년/반/번호/이름 → 대상 과제 → 제출 코드 → 파일 → 확인 → 진행률 → 확인번호. 재제출은 이전 확인번호 필수. 교사: 대시보드, 과제 관리, 제출 현황, 학생 관리, 전체 다운로드, 설정. 흰 배경·파란 강조·큰 입력·키보드 포커스·한국어 안내.

## 데이터
classes(학년/반/최대번호), students(학년/반/번호 고유), assignments(기간/대상/허용확장자/용량/재제출/지각/제출코드 해시), submissions(학생 식별/확인번호 해시), versions(파일 고유명/원본명/크기/SHA256/시각), admins(비밀번호 scrypt), sessions(토큰 해시/CSRF/만료), settings(기본 용량/보유일), audit(자료 내용 없는 작업 기록).

## 보안과 일관성
익명 API는 학급 설정과 대상 과제만 공개. 조회/다운로드는 관리자만. 제출 코드와 재제출 확인번호는 서버에서 해시 검증. 확인번호는 등록 성공 때만 1회 반환하며 유실 시 교사가 과제별 이력에서 재설정. 파일은 임시 디스크 업로드 후 검증, 고유명 이동, DB 트랜잭션 커밋 순서. 실패/경쟁 제출은 임시 파일 제거. 학생 번호 사칭의 한계는 안내. 원본 제출물 실행/미리보기/압축 해제 금지. ZIP 기반 문서의 구조와 크기/위험 항목을 검증하되 백신 대체 불가.

## 완료 기준
실제 API와 SQLite로 제출·로그인·개별/ZIP 다운로드·재제출 이력·명단 기반 미제출·CSV·재시작 유지·백업/복원 테스트. 클라이언트 빌드 성공. 테스트가 통과해도 학교 HTTPS/방화벽/실제 브라우저·300명 부하·백신 검사는 따로 보고한다. 실제 운영 승인을 대신하지 않는다.
