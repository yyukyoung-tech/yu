# GitHub 공개와 Pages

이 앱은 Node 서버·SQLite·비공개 파일 저장소가 필요한 웹앱입니다. GitHub Pages는 이 서버를 실행할 수 없습니다. 따라서 Pages에는 개인정보 입력 폼이 없는 **접속 안내 페이지**만 배포합니다. 전체 소스는 GitHub 저장소에 보관하며, 실제 과제 서버는 학교가 승인한 환경에서 실행해야 합니다.

Pages 출력은 `pages-dist/index.html`과 `.nojekyll`뿐입니다. 학생 DB·원본 파일·백업·관리자 비밀번호·`.env`·서버 코드는 배포 아티팩트에 포함하지 않습니다. 서버를 아직 지정하지 않았다면 “학교 서버 연결 대기”를 표시하고 제출 버튼을 제공하지 않습니다. 성공한 것처럼 표시하거나 브라우저에 임의 저장하지 않습니다.

## 배포
GitHub 저장소 Settings → Pages → Source를 **GitHub Actions**로 선택합니다. main 브랜치에 올리면 `.github/workflows/pages.yml`이 테스트·빌드·운영 의존성 보안검사 후 Pages 안내 페이지만 배포합니다. Actions는 공식 액션의 확인된 커밋에 고정했으며, 배포 작업만 Pages 쓰기/OIDC 권한을 가집니다. 비밀번호나 PAT를 워크플로 파일에 넣지 않습니다.

학교가 승인한 서버를 준비하면 Settings → Secrets and variables → Actions → Variables에 `SCHOOL_SERVER_URL`을 등록하고 배포 워크플로를 다시 실행합니다. 예: `https://과제.학교승인주소`. 값에는 사용자 이름·비밀번호·토큰·쿼리를 넣지 않습니다. 이 주소는 공개 페이지에 표시될 수 있는 공개 설정입니다. 서버의 내부 주소 공개가 허용되는지도 학교에서 확인해야 합니다. URL은 HTTPS 루트 주소만 허용합니다.

실제 서버의 인증·쿠키는 해당 서버에서 직접 처리합니다. Pages에서 개인정보 API를 호출하거나 교차 사이트 쿠키 보안을 완화하지 않습니다. 학교 내부 서버라면 같은 학교 네트워크의 학생만 연결될 수 있습니다. Pages와 교사 관리 화면의 접근 권한은 서로 다릅니다.

## 공개 제외
`.gitignore`는 `.env*`(예시 제외), SQLite·DB, 인증서/키, 데이터·파일·업로드·백업·런타임 폴더, 생성 ZIP, 브라우저 검증 스크린샷을 제외합니다. 실제 운영 자료는 소스 폴더 밖에서 보관하며 서버가 소스/공개 폴더 안의 데이터 저장 설정을 거부합니다. 임의의 파일명으로 저장한 개인정보까지 자동 탐지한다는 뜻은 아니므로 실제 자료를 프로젝트 폴더에 복사하지 마세요.

코드는 공개되어도 학생 자료는 공개해서는 안 됩니다. 테스트의 가상 비밀번호와 가상 학생은 운영 계정이 아니며 실제 서버에는 기본 계정이 생성되지 않습니다. 공개 저장소는 출처·권한·학교 정책에 따라 검토해야 합니다.
