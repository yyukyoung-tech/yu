# 학교 서버 운영 안내

## 학교 접속 설정

학교 담당자에게 내부 서버 주소, HTTPS 인증서, 방화벽 허용 범위와 개인정보 처리 승인을 확인받으세요. 승인받지 않은 외부 서버에 게시하지 않습니다. 학생과 교사는 배포된 HTTPS 주소만 브라우저로 접속합니다. 운영자만 서버 소프트웨어를 설치합니다.

권장: 학교 HTTPS 역방향 프록시 → 서버의 `127.0.0.1:4310` 연결. `.env` 예시:

```dotenv
NODE_ENV=production
APP_ORIGIN=https://과제함.학교승인도메인
HOST=127.0.0.1
PORT=4310
TRUST_PROXY=1
DATA_DIR=D:/SchoolPrivate/AssignmentBox
```

예시 도메인은 실제 주소가 아닙니다. 프록시에서는 TLS 인증서 검증을 유지하고 원래 Host 및 X-Forwarded-For/Proto를 올바르게 설정하세요. `TRUST_PROXY=1`은 백엔드 포트에 다른 PC가 직접 접근할 수 없는 신뢰된 단일 프록시 환경에서만 사용합니다. 요청 최대 크기를 서버 설정에 맞게 허용하고 업로드/응답 제한시간은 5분 이상으로 정합니다. 첫 버전은 서버 한 프로세스만 실행합니다.

직접 TLS를 제공할 수도 있습니다. 학교가 제공한 인증서 경로를 `TLS_CERT`, 비공개 키를 `TLS_KEY`에 지정하고 `APP_ORIGIN=https://실제학교주소:4310`, `HOST=학교내부IP`, `TRUST_PROXY=0`으로 설정합니다. 비공개 키는 소스 폴더에 넣지 않습니다. 인증서 경고를 무시하거나 백신·Windows 보안을 끄지 마세요.

학교 컴퓨터실에서 주소를 열어 잠금 표시와 인증서가 정상인지 확인합니다. 학생 화면·교사 로그인·한글 파일 제출·다운로드·다른 학생 자료 접근 차단을 가상 자료로 확인한 다음 실제 자료 운영을 결정하세요. 서버 시간 동기화를 유지합니다. 저장 시각은 UTC, 브라우저 표시 시각은 접속 PC의 현지 시간입니다.

## 용량·동시성·접근 제한

초기 10개 반/최대 번호 30, 등록 인원 제한은 별도로 두지 않습니다. 기본 50MB, 설정 허용 1~500MB입니다. 과제 제한과 서버 전체 제한 중 더 작은 값이 적용됩니다. 32개 소용량 파일 동시 제출을 검증했으며, 300명 동시 50MB 전송이나 장기 운영을 보증하는 결과는 아닙니다. 실제 환경의 디스크 여유 공간·CPU·네트워크·프록시 제한을 확인하세요. 매 제출마다 파일은 새 고유명으로 보존됩니다. 최대 자료량은 제출 버전 수에 비례합니다.

한 IP당 로그인은 15분에 10회, 제출은 10분에 150회 제한합니다. 학교 전체가 같은 NAT를 사용하면 제한을 공유합니다. 학교가 사용하는 프록시에서 실제 IP 전달과 방화벽을 확인하세요. 재시작 시 요청 제한 카운터는 초기화됩니다. 관리자 세션은 2시간 후 만료됩니다. 교사 비밀번호는 scrypt 해시, 세션·확인번호·제출 코드는 SHA-256 해시로 저장합니다. 제출 코드는 가능한 길고 추측하기 어렵게 정하세요.

## 파일 검사 범위

텍스트/파이썬은 UTF-8·NUL/실행파일 검사, PDF/이미지/HWP는 파일 시그니처, OOXML/HWPX/ZIP은 압축 목차·필수 구성/위험 확장자·경로/암호화/압축 해제량·항목 수 제한을 검사합니다. 엔트리는 gzip/TAR 헤더·체크섬·프로젝트 경로를 검사합니다. ZIP 문서는 서버에 압축 해제하지 않습니다. 파이썬 등 제출 코드는 실행하지 않으며 모든 파일은 첨부 다운로드로만 제공합니다.

**악성코드 완전 탐지나 문서 전체 유효성 검사는 아닙니다.** 백신 연동/격리 분석은 포함하지 않습니다. 학교 보안 정책에 맞게 허용 형식을 좁히고, 교사는 받은 파일을 학교의 보안 절차로 확인하세요. 레거시 CP949 텍스트는 UTF-8로 저장해야 합니다. 엔트리 형식은 [공식 문서](https://docs.playentry.org/entryjs/file/2024-07-24-ent.html)에 근거했습니다.

## 운영 점검과 장애

시작 전 데이터 폴더 권한·디스크 공간·백업을 확인하세요. 파일 쓰기/DB 저장 실패에는 확인번호를 반환하지 않습니다. 업로드 중 연결이 끊기면 저장 완료 여부가 불확실할 수 있으므로 교사 현황에서 확인하세요. 확인번호 없이 중복 제출로 기존 자료를 덮어쓰지 않습니다. 프로세스가 강제 종료되면 임시/고아 파일이 남을 수 있습니다. 직접 삭제하기 전에 백업하고 서버 담당자가 DB 참조 여부를 확인해야 합니다.

정기적으로 백업을 생성하고 별도 새 폴더 복원과 실제 파일 읽기를 점검하세요. 보유기간 삭제는 백업을 지우지 않습니다. 삭제/폐기 대상에는 외장 백업과 내보낸 파일도 포함합니다. 로그에 학생 이름·파일 내용·비밀번호·확인번호를 기록하지 마세요. API 오류는 상세 SQL/경로를 사용자에게 노출하지 않습니다. 감사 API `/api/admin/audit`는 관리자 인증 후 최근 작업 코드·대상 ID·시각만 반환합니다.

## 배포 형태

`dist`는 브라우저 화면 빌드이며 이것만 정적 호스팅하면 제출 기능은 작동하지 않습니다. `server`와 비공개 DB/파일 저장소를 함께 운영해야 합니다. 제공 ZIP에는 전체 소스와 빌드·명령이 포함되며 Node 런타임과 의존성 설치본은 포함되지 않습니다. 외부 게시·인증서 구매·공개 배포·Windows 서비스/방화벽 설정을 자동 수행하지 않았습니다.

Windows EXE 설치 파일은 만들지 않았으므로 앱 코드 서명은 해당하지 않습니다. 웹사이트에는 학교가 승인한 유효한 HTTPS 인증서가 필요합니다. 자동 업데이트는 없습니다.
